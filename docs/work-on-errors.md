# Работа над ошибками: план

Цель: по неверным ответам ученика нейросеть определяет, **почему** он ошибся (невнимательность,
знак, единицы, не та формула…), и подбирает ему задачи, которые стоит решить.

## Принятые решения

- Ответы ученика и разбор ошибок видит **только преподаватель**. Ученик не видит ни журнал, ни причины —
  он получает только задачи, которые ему выдали.
- Разбор и подбор задач идут **на сервере**. В браузере ученика только сбор.
- Хранение в браузере — временное, до появления сервера. Перенос прогресса между устройствами
  отдельно не делаем: с сервером он появится сам.

## Этапы

| Этап | Что появляется | Состояние |
| --- | --- | --- |
| 0 | Сбор: каждый ответ, время, подсказки | сделано |
| 1 | Журнал уходит на сервер, преподаватель видит ошибки учеников | ждёт сервера |
| 2 | Разбор причины нейросетью | ждёт сервера |
| 3 | Подбор задач и выдача ученику | ждёт сервера |

## Этап 0. Сбор — сделано

Раньше сайт помнил только число ошибок в задаче. Теперь он ведёт журнал попыток (`src/api/attempts.js`):

- каждый отправленный ответ как есть — и неверный, и верный, и неразобранный («8 м/с»);
- взятые подсказки и «Я не знаю»;
- сколько времени задача была на экране до каждого действия;
- отметка о сбросе прогресса (сам журнал сброс не стирает).

Ограничения, пока нет сервера:

- журнал лежит в браузере ученика (ключ `edu-attempts-v1`), преподаватель его не видит;
- очистка браузера или смена телефона журнал стирает;
- время — оценка: считается, пока вкладка открыта и задача на экране. Ученик мог решать на бумаге
  или отойти, поэтому один промежуток ограничен часом.

## Этап 1. Сервер

1. События журнала уходят на сервер — таблица `attempts` с теми же полями, что сейчас.
2. При первом входе ученика накопленный в браузере журнал загружается на сервер, чтобы собранное
   до сервера не пропало.
3. Ученику сервер журнал не отдаёт.
4. Преподаватель видит: по ученику — его трудные задачи (больше ошибок, дольше думал, «Я не знаю»);
   по задаче — частые неверные ответы всей группы. Если один и тот же неверный ответ дают многие,
   дело в задаче или в объяснении темы, а не в ученике.

## Этап 2. Разбор нейросетью

**Что получает нейросеть:** условие задачи, верный ответ, разбор, критерии проверки (поле уже есть
в редакторе), все ответы ученика по порядку с временем и подсказками. Если ученик приложил фото
решения — ещё и фото: по нему причина видна гораздо точнее, чем по одному числу.

**Что возвращает** (строго по форме, чтобы результат можно было хранить и считать):

- причина — одна из справочника ниже;
- уверенность — высокая / средняя / низкая;
- навык, которого не хватило (из справочника навыков, этап 3);
- одно-два предложения для преподавателя: где именно ошибка.

**Справочник причин** (черновик, утверждает преподаватель):
невнимательность · арифметика · знак или направление · единицы и перевод в СИ · порядок величины ·
округление · не та формула или закон · не понял условие · формат ответа · угадывал · не определить.

**Как не тратить лишнего:**

- часть ошибок числового ответа сервер узнаёт правилами, без нейросети, сравнивая неверный ответ с верным:

  | Признак | Причина |
  | --- | --- |
  | отличается только знаком | знак, направление оси |
  | отличается в 10, 100, 1000 раз | порядок величины, приставки (кило-, милли-) |
  | отличается в 3,6 / 60 / 3600 раз | перевод единиц (км/ч и м/с, минуты и секунды) |
  | отличается в 2 раза | потерян или лишний множитель ½ |
  | верный с другим округлением | округление |
  | в задаче с несколькими полями ответы перепутаны местами | невнимательность |
  | ввод не разобран | формат ответа (единицы в поле) |

- разбор хранится по паре «задача + неверный ответ». Тот же ответ у другого ученика второй раз
  не разбирается — для популярных ошибок это основная экономия;
- разбор идёт после завершения задачи, а не на каждый ответ.

**Как проверить качество:** преподаватель вручную размечает 50–100 ошибок, сверяем с нейросетью.
Разборы с низкой уверенностью в подбор задач не идут, пока преподаватель их не подтвердит.

## Этап 3. Подбор задач и выдача ученику

1. Справочник навыков: «проекции на ось», «перевод единиц», «график скорости», «второй закон Ньютона»…
2. У каждой задачи в редакторе — один-три навыка.
3. Причина ошибки + навык → сервер подбирает задачи на этот навык, которые ученик ещё не решал.
4. Если такой задачи в курсе нет — нейросеть готовит черновик, преподаватель утверждает его в редакторе.
   Без утверждения сгенерированная задача к ученику не попадает.
5. Ученик видит подобранные задачи отдельным списком — без объяснения, почему они ему выданы.
6. Повторение: задача на тот же навык возвращается через 1, 3 и 7 дней, пока не решена без ошибок.

## Что ещё нужно решить преподавателю

1. Справочник причин — утвердить или поправить список из этапа 2.
2. Кто размечает навыки у задач: преподаватель вручную или нейросеть предлагает, а он подтверждает.
3. Выдача задач: сервер выдаёт подобранное сам или преподаватель сначала просматривает подборку.
4. Использовать ли в разборе фото решений.
5. Персональные данные: ответы учеников уходят нейросети без имени и почты; сервер — в России (152-ФЗ).

## Что делать до сервера

Ничего сверх сбора: всё остальное живёт на сервере. Журнал копится в браузерах учеников
и загрузится на сервер при первом входе.
