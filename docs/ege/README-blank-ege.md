# Модуль «Бланк проверки ЕГЭ по физике»: передача агенту, который собирает сайт

Это один из модулей будущей платформы репетитора по физике (подготовка к ЕГЭ, группы до 5–6 учеников). Модуль уже работает как самостоятельная HTML-страница. Задача агента: перенести его в платформу, сохранив логику, внешний вид и принятые решения, и заменить локальное хранение на базу сайта.

Файлы в пакете:

| Файл | Что это |
|---|---|
| `README-blank-ege.md` | Этот документ: всё, что нужно знать |
| `blank-ege.html` | Эталонная рабочая реализация (один файл, без сборки). Открывается в Chrome двойным щелчком |
| `ege-data-sample.json` | Пример файла данных в текущем формате |

Пользователь: преподаватель (Данил Денисович). Проверяет пробники учеников, выставляет первичные баллы по заданиям, показывает ученику результат и отправляет ему картинку-карточку.

---

## 1. Что делает модуль

1. Преподаватель выбирает ученика и пробник, тапает балл за каждое из 26 заданий.
2. Сразу видно: первичный балл (из 45), тестовый (из 100) по официальной шкале, прогресс к порогу 36 и к личной цели ученика, баллы по темам.
3. История пробников ученика: график роста тестового балла и список пробников.
4. Список учеников с целями.
5. Кнопка «Карточка для ученика»: генерирует PNG 1080×1520 с результатом, его отправляют ученику.

## 2. Структура ЕГЭ по физике 2026 (источник: методические рекомендации ФИПИ 2026)

### Максимальные баллы по заданиям (всего 45)

```

Макс:    1 1 1 1 2 2 1 1 2 2  1  1  1  2  2  1  2  2  1  1  |  3  2  2  3  3  4
```

Часть 1: задания 1–20 (28 баллов). Часть 2: задания 21–26 (17 баллов).

### Перевод первичных баллов в тестовые (индекс = первичный балл 0..45)

Минимальный порог: 36 тестовых (8 первичных). Шкалу дал преподаватель. Её стоит держать в настройках, а не прошивать в коде, потому что она может меняться по годам.

### Темы и цвета (утверждены преподавателем, менять нельзя)

## 3. Модель данных

Две сущности. Сейчас они хранятся одним JSON-файлом (см. `ege-data-sample.json`).

**Student (ученик)**
| Поле | Тип | Смысл |
|---|---|---|
| id | string | идентификатор |
| name | string | имя, до 60 символов |
| goal | int | цель в тестовых баллах, 36..100, по умолчанию 80 |
| createdAt | int (ms) | время создания |

**Exam (пробник)**
| Поле | Тип | Смысл |
|---|---|---|
| id | string | идентификатор |
| studentId | string | ссылка на ученика |
| title | string | например «Пробник 3», до 60 символов |
| date | `YYYY-MM-DD` | дата пробника |
| createdAt | int (ms) | время создания, второй ключ сортировки после даты |
| scores | object | `{"<номер задания>": балл}` |

Значения в `scores`:
- ключа нет: задание ещё не проверено;
- `0..max`: выставленный балл;
- `-1`: «не решал» (не приступал). Даёт 0 баллов, считается проверенным, на карточке показывается «н/р».

Служебное (только в локальной версии): `_t` (время последнего изменения записи, мс) и `deleted` (`{"exams/<id>": время удаления}`). Нужны для слияния копий без потери данных. В базе сайта их заменяют обычные `updated_at` и мягкое удаление.

### Расчёты (функция `calc` в `blank-ege.html`)
- первичный = сумма баллов (без `-1`); тестовый = `CONV[первичный]`;
- по частям: часть 1 (1–20), часть 2 (21–26);
- по темам: набрано / потеряно / максимум;
- потеряно = сумма (макс. − балл) по проверенным заданиям; «не решал» теряет максимум;
- «до порога» и «до цели» = минимальный первичный, при котором `CONV[p] >= порог`, минус текущий первичный.

Контрольный пример: пробник `ex_2` из `ege-data-sample.json` даёт 14 первичных и 48 тестовых. По темам: механика 5/14, МКТ 5/11, электродинамика 2/13, квантовая 0/3, методы 0/2, сквозное 2/2.

## 4. Экраны и поведение

Навигация вверху: «Проверка», «История», «Ученики», справа выбор ученика.

**Проверка**
- Выбор пробника и кнопка «+ Пробник» (новый получает название «Пробник N» и сегодняшнюю дату).
- Легенда тем, затем часть 1 и часть 2. На широком экране каждая часть в две колонки.
- Строка задания: номер с цветной полоской темы слева, кнопки `–` (не решал), `0`, `1` … `max`. Тап ставит балл, повторный тап по тому же баллу снимает его.
- Цвет состояния задания: зелёный (полный балл), жёлтый (частичный), красный (0), серый зачёркнутый (не решал), без цвета (не проверено). Цвета состояния и цвета тем разные, их нельзя смешивать.
- Справа карточка итога: крупный тестовый балл, «N из 45 первичных», полоса прогресса, плашки «порог 36 пройден / до порога», «до цели», «потеряно», «не решал», полоски по темам, минималистичный график перевода (без сетки: кривая шкалы, пройденный участок выделен, пунктиры порога и цели, точка «14 → 48»).
- На телефоне задания идут первыми, сверху липкая мини-полоска «14/45 → 48».

**История**: график тестового балла по пробникам (пунктиры порога и цели, клик по точке открывает пробник). Под ним список пробников (дата, название, первичный, тестовый). Нажатие на строку раскрывает редактирование названия и даты, кнопки «Открыть» и «Удалить» (удаление с подтверждением вторым нажатием).

**Ученики**: список (имя, цель, число пробников, последний тестовый балл), добавление, изменение, удаление с подтверждением (вместе с пробниками). В локальной версии здесь же блок «Данные».

**Карточка для ученика (PNG)**: имя, пробник и дата, крупный тестовый балл, первичный, части 1/2, 26 клеток заданий (метка темы сверху, балл `x/max`, «н/р» или точка, если не проверено), блок «По темам», график перевода. Рисуется на canvas, шрифт Onest.

## 5. Дизайн (утверждённые решения)

- Преподаватель просил: легко, современно, компактно, без перегруза. Первая версия была отклонена как тяжёлая (засечки, сетка на графике, всё на одном экране).
- Шрифт **Onest** (Google Fonts), без засечек. Без моноширинных шрифтов.
- Светлый фон `#F5F6F8`, карточки белые со скруглением 14px и тонкой обводкой, акцент `#3A5BD9`. Есть тёмная тема.
- Графики минимальные: без сетки и лишних осей.
- Цвета тем фиксированы (см. раздел 2).
- Все тексты интерфейса по-русски, коротко. Длинные тире («—») в текстах не использовать.

## 6. Хранение сейчас и что сделать на платформе

**Сейчас (`blank-ege.html`)**: страница открывается локально в Chrome/Edge и через File System Access API пишет все данные в `ege-данные.json` после каждого балла (запись с задержкой 350 мс, а при закрытии вкладки сразу). Копия также лежит в localStorage. Есть «Скачать копию» и «Загрузить копию». Копии объединяются по времени изменения записи, удалённое не возвращается. В коде хранилище отделено от логики: интерфейс работает с объектом `db` (`collection(name).onSnapshot`, `doc("students/<id>").set / delete`). Его реализует отдельный `<script>` (шим), поэтому хранилище легко заменить.

**На платформе** рекомендуется:
1. Таблицы `students`, `exams` (scores как JSONB или отдельная таблица `exam_scores(exam_id, task_no, value)` со значениями `-1..4`), плюс `teacher_id`, `updated_at`, мягкое удаление.
2. Роли: преподаватель видит и правит всех своих учеников; ученик в будущем видит только свои пробники и карточку (только чтение).
3. Импорт: принять `ege-данные.json` текущего формата (раздел 3) и загрузить в базу, чтобы перенести накопленные данные.
4. Сохранять балл сразу после тапа (оптимистичное обновление), с индикатором «сохранено / сохраняю / не сохранилось».
5. Шкалу перевода, порог и разбивку по темам держать в конфиге или таблице.
6. Генерацию карточки оставить на клиенте (canvas), см. `drawCard` в эталоне.

## 7. Ошибки, которые уже были найдены и исправлены (не повторить при переносе)

- Подключение файла не должно затирать данные, введённые до подключения: нужно сливать по времени изменения, а не заменять.
- Удалённые записи не должны «воскресать» из старой копии.
- Нельзя перезаписывать чужой или повреждённый JSON: проверять формат перед записью.
- Две открытые вкладки не должны затирать друг друга.
- Последний балл перед закрытием вкладки должен сохраниться.
- Повторный рендер списка не должен сбивать фокус в поле, где преподаватель печатает (название пробника).
